### Key Findings & Structural Patterns

1. **Instruction-Level Verification vs. Live In-Game Boot Verification**:
   The most significant finding of this audit is that two major items claimed as `"✅ Verified in-game"` in `README.md` explicitly state in their source documentation that they were **never loaded in-game**:
   - **Row 7 (Inventory Add)**: `docs/SO2-INVENTORY-ADD-INVESTIGATION.md` line 29 admits: *"Not loaded in-game. This establishes the mechanism with instruction-level evidence, not a completed emulator test."*
   - **Row 12 (Party Recruitment)**: `docs/SO2-PARTY-MEMBER-INVESTIGATION.md` line 1307 admits: *"Not loaded in-game. This uses the known original early-game S13... remains bounded instruction execution, not a PS1 load test."*
   Both items have bulletproof disassembly and harness execution proof, but their live emulator testing in DuckStation was never completed. They are categorized as **REAL GAPs** and detailed below as actionable follow-up tasks.

2. **The "Compressed 6-Slot" Phantom Format**:
   - **Row 9 (Equipment 6-Slot)**: In early repo history prior to the discovery of the zero-run codec (`00 00 N`), inspecting raw memory-card blocks gave the impression that some characters had a 6-slot equipment structure while others had 7 slots. In reality, all characters in the decoded save buffer have a uniform 7-slot record (`0x4A0 + slot*0xD0 + 0x0C..0x19`); an empty second accessory is simply `0x0000`. Presenting "compressed 6-slot" as a verified feature in the README documents a compression artifact rather than a real save structure, while `scripts/so2_equip.py` still operates under obsolete raw-block heuristics.

3. **Legacy Hex-Poking Vestiges**:
   - **Row 2 (Stats)**: The note `(999 safe; 9999 unproven)` was a legacy holdover from raw card poking. The actual decoded storage is a 3-stage stat triplet (base, intermediate, final) accessed via resident getters/setters `80033218`/`800332F8` at `0x1A0 + slot*0x60`. This has been corrected inline in `README.md`.

### Row 9: Equipment — compressed 6-slot (missing one accessory)
- **README Claim**: `✅ Verified`
- **Audit Verdict**: **REAL GAP, NEEDS ITS OWN TASK**
- **Justification**: The concept of a "compressed 6-slot" character is a phantom format born from diffing raw memory-card blocks under zero-run compression (`00 00 N`) prior to September 2026. In the true decoded save buffer, **all** 8 party members have uniform 7-slot equipment arrays (`0x4AC + slot*0xD0`); an unequipped second accessory is simply stored as `0x0000`. `scripts/so2_equip.py` still embeds obsolete 6-slot heuristics on raw blocks, and the README presents a compression artifact as a verified save format variant.
- **Actionable Scope**: Dedicated follow-up task to refactor `scripts/so2_equip.py` to use `so2_codec.state()` on decoded saves, eliminate the obsolete 6-slot code paths, and update documentation.
- **MANAGER REVIEW CORRECTION (2026-09-28):** This verdict is itself wrong and was not acted on. `scripts/so2_equip.py` deliberately reads/writes the **raw, still-compressed** memory-card bytes directly (the same anchor-and-walk-backward technique as `so2_refill_sp.py`), not the decoded buffer - see the tool's own docstring and `equip_slots()`. Under the zero-run codec, a genuinely empty accessory-2 slot really does compress to a shorter 6-value byte run on the raw card; that is real, necessary behavior for a tool operating at that level, not a phantom format. `docs/SAVE-FORMAT.md` (lines 220-247) already documents this correctly, explicitly labeled "Compressed (6 slots...)" as a raw-block observation, alongside the separately-correct fact that the *decoded* buffer always has a fixed 7-slot layout - the two describe the same data at different representation levels and do not contradict each other. This row's "Verified" claim stands; **no follow-up task was created for it.** The audit's broader methodology (checking hedge language against real evidence) is sound and caught two genuine gaps elsewhere (Rows 7, 12) - this one specific verdict just didn't hold up under a second look, which is itself the kind of check this audit exists to enable.
